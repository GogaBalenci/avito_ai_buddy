### 4.2 `10` §10, `11` §3.12 — ответ `confirm`
Ответ `POST /api/actions/{action_id}/confirm` — `{result: RequestView, reply: AgentReply}`. `RequestView` — единый вид заявки (отгул и доступ) для карточек, истории, «Моих заявок» и «Входящих» (`12` §6). Поля `10` (`request_id`, `status`, `date_from`, `date_to`, `working_days`) и `11` (`request`) в нём есть. Так же — `GET /api/requests` и `GET /api/mentor/access-requests` (`RequestList`).

### 4.3 `10` §11.6, `11` §0.3 — флаги имитаций
Флаги `mock_absences_fault` и `access_mentor_approval` хранит `mcp-mocks` в таблице `mock_admin.flags` (это `FlagProvider` имитации). `POST /api/demo/flags` проверяет белый список и проксирует изменение в `MCP_MOCKS_ADMIN_URL/demo/flags`. Флаги приложения (`llm_enabled`, `llm_rephrase`) — в `app.feature_flags`. Белый список и поведение не меняются.

### 4.4 `10` §14, §19, `11` §5 — тесты гонок
Вопрос «testcontainers или PostgreSQL из compose» закрыт: PostgreSQL из compose (`docker compose --profile test run --rm test-go`), отдельная БД на пакет из шаблона. Строку в §14 `10` «(testcontainers или compose в CI, решение — `12`)» заменить на «(PostgreSQL из compose, `12` §11)»; пункты в «Открытых вопросах» удалить.

### 4.5 `11` §1.14 — метрика «неделя 1 вовремя»
Представление `path_steps_cache` заменяется таблицей `app.path_period_stats(user_id, period, done, total, updated_at)`, которую обновляет `GET /api/path`. В SQL метрики `(SELECT count(*) FROM path_steps_cache …)` заменить на `(SELECT total FROM app.path_period_stats s WHERE s.user_id = e.user_id AND s.period = 'week1')`; фразу «окончательно — `12`» удалить.

### 4.6 Клиентские события (`09` §8.2, §12; `11` §1.14, §2.6.5; этот патч §1.4)
События `escalation_copied`, `doc_conflict_reported`, `next_step_clicked` клиент отправляет через `POST /api/client-events {name, reply_id?, step_id?}`. Имя — из белого списка; остальные поля сервер берёт из сохранённого ответа и сессии. `doc_conflict_reported` записывается не больше одного раза на `reply_id` (уникальный индекс в `app.events`). В `AgentReply.actions[]` у действия `copy` есть поле `copy_event` — какое событие отправить после копирования.

### 4.7 `10` §8.1, `11` §0.5 — состояние `expired`
`GET /api/actions/{action_id}` (и `pending_action.state`) отдают вычисляемое состояние `expired`, если черновик в `active` и `now > expires_at`. В Redis состояние не меняется — это только вид для карточек истории.

### 4.10 Проверка `Origin` (`09` §11.7, `10` §8)
