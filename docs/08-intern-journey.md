Источники: два CSV чек-листа Авито, `06-checklist-analysis.md` (нумерация шагов — оттуда), `05-avito-sources.md` (боли стажёров из статей), `02-decisions.md` (сценарии S1–S4).

## Путь стажёра

### Рамка
- **Горизонт:** первые 4 недели. В чек-листе Авито это периоды «1 неделя», «2 неделя» и «1 месяц». Шаги «1 месяца» мы раскладываем на недели 3–4 — **это допущение команды**, в CSV порядка внутри периода нет.
- **Состав:** общие шаги для всех направлений («Материалы для всех») + модуль Backend («Чек-лист Backend»). Backend — единственный трек на реальных данных Авито.
- **Роли шагов** (С — стажёр, Н — наставник, Р — руководитель, К — куратор) выведены из формулировок: в CSV нет колонки «кто выполняет» (см. `06`).
- **Стажёр в интерфейсе видит только свои шаги (С).** Шаги наставника приведены ниже для контекста, в MVP они не показываются.
- **Контекст стажёра (из `05`):** стажировка — 20–40 ч в неделю, многие совмещают её с учёбой; у каждого есть наставник и еженедельные 1:1; первый день уходит на оформление, окружение и запрос доступов.

### Обозначения
- Тип шага: 📘 изучить · 🔧 настроить · 🔑 доступ/запрос · 👥 встреча/люди · 🎤 рассказать · 📋 оргшаг
- Польза бадди: ⭐⭐⭐ высокая (снимает обращение к наставнику или оргдействие) · ⭐⭐ средняя (объяснение со ссылкой) · ⭐ низкая (только трекинг в «Моём пути»)
- Источник объяснения для S2: **P** — Playbook, **К** — PDF кейса, **О** — публичный инструмент (только общее описание), **Т** — источника нет: «тестовое описание, уточни у наставника»

### Этапы по времени
| Этап | Дни от старта | Цель этапа | Ощущение стажёра |
|---|---|---|---|
| Неделя 1 — «Вход в команду» | 1–7 | Познакомиться, получить каналы и доступы, понять принципы | Много нового, непонятно, что важно и к кому идти |
| Неделя 2 — «Инструменты и платформа» | 8–14 | Разобраться в документации команды, платформе и Go | Тонет в документах и внутренних терминах |

### Событие вне чек-листа: отгул (в любой момент) — S3
- **Ситуация (пример из кейса):** стажёру нужен отгул, он не знает принятого порядка и не уверен, стоит ли отвлекать руководителя. Повод реалистичен: многие стажёры совмещают работу с учёбой (`05`), поэтому отгул на экзамен — частая ситуация.
- **Где застревает:** не знает порядка; боится выглядеть безответственным; не знает, в какой сервис идти.
- **Польза бадди:** ⭐⭐⭐ — объясняет тестовый порядок → форма «от — до» → подтверждение → заявка в имитацию сервиса отсутствий → номер и статус сохраняются и видны в «Моём пути» и истории. Общение с наставником бадди не заменяет: подсказывает предупредить его.
- В UI: «тестовый порядок, не регламент Авито».

## Треки

### Идея
Путь стажёра = **общий трек** (`common`) + **трек направления** (`backend`, `frontend`, …). Трек — это данные, а не код: каждый — отдельный YAML-файл в `tracks/`. Код знает только формат файла.

```
tracks/
  track.schema.json   # JSON Schema формата (контракт)
  common.yaml         # «Материалы для всех» (CSV Авито) + периоды
  backend.yaml        # «Чек-лист Backend» (CSV Авито)
  frontend.yaml       # синтетический, тестовый
```

Что даёт формат:
- **S1:** шаги, периоды, порядок и тип берутся из трека; «Что дальше» работает одинаково для любого направления.
- **S2:** шаг ссылается на документ базы знаний и на уровень источника — отсюда пометка «тестовое описание, уточни у наставника».
- **S4:** шаг-запрос ссылается на ресурс в каталоге имитации доступов — кнопка «Запросить доступ» появляется без кода.
- **Внедряемость:** в проде YAML заменяется на ответ реального сервиса чек-листа новичка через тот же MCP-endpoint `checklist`; контракт шага остаётся прежним.

### Формат файла трека (`schema_version: 1`)

**Поля трека**
| Поле | Обяз. | Значения | Смысл |
|---|---|---|---|
| `schema_version` | да | `1` | Версия формата |
| `id` | да | `[a-z][a-z0-9-]*` | Идентификатор трека; совпадает с именем файла |
| `title` | да | строка | Название в UI |
| `kind` | да | `common` \| `direction` | Общий трек или направление |
| `extends` | для `direction` | `common` | Какой трек подмешивается |
| `synthetic` | да | `true` \| `false` | Тестовый трек, составлен командой |
| `disclaimer` | если `synthetic: true` | строка | Плашка в UI на каждом шаге трека |
| `source` | да | строка | Откуда взяты шаги |
| `periods` | только в `common` | список | Периоды с границами в днях от старта |
| `steps` | да | список | Шаги |

**Поля периода** (`common.yaml`): `id` (`week1`, `week2`, `month1`, `month2`, `month3`, `after3`), `title`, `from_day`, `to_day` (у последнего — `null`).

**Поля шага**
| Поле | Обяз. | Значения | Смысл |
|---|---|---|---|
| `id` | да | `<префикс>-<код>`, уникален в паре common + направление | Стабильный ключ прогресса в БД |
| `checklist_ref` | нет | `"1.13"` | Номер из `06` — трассировка к чек-листу Авито |
| `period` | да | id периода | Этап в «Моём пути» |
| `order` | да | целое, шаг 10 | Порядок внутри периода; шаг 10 оставляет место для вставок |
| `title` | да | строка в повелительном наклонении | Текст шага |
| `type` | да | `learn` \| `setup` \| `access` \| `meet` \| `tell` \| `org` | Иконка и тип (📘🔧🔑👥🎤📋) |
| `owner` | да | `intern` \| `mentor` \| `lead` \| `curator` | Кто делает. Стажёр видит только `intern` |
| `help.kind` | да | `explain` \| `access_request` \| `ask_mentor` \| `track_only` | Что делает бадди на шаге |
| `help.kb_doc` | для `explain` | slug документа базы знаний | Ссылка на источник ответа |
| `help.source_level` | для `explain` | `playbook` \| `case` \| `public` \| `none` | `none` → «тестовое описание, уточни у наставника» |
| `help.resource` | для `access_request` | id ресурса в каталоге `access` | Что запрашиваем в S4 |
| `synthetic` | нет | `true` | Шаг-синтетика внутри реального трека (по умолчанию — как у трека) |

**Правила проверки загрузчика** (они же — тест в CI, падение = красная сборка):
1. Файл соответствует `track.schema.json`.
2. `id` трека совпадает с именем файла; у `direction` есть `extends: common`.
3. `id` шагов уникальны в объединении common + направление.
4. `period` существует в `common.yaml`.
5. `help.kb_doc` есть в сидах базы знаний; `help.resource` есть в каталоге имитации `access`.
6. `synthetic: true` → `disclaimer` не пустой.
7. В тексте шагов нет имён реальных людей. Так, «список от директора центра разработки» хранится без имени из CSV: минимизация ПДн.

### Как добавить новый трек без изменения кода
**Что делает код (один раз, для любого трека):**
1. При старте и по кнопке «Сбросить демо-данные» загрузчик читает **все** `tracks/*.yaml`, проверяет их по правилам выше и складывает шаги в таблицы `tracks` и `track_steps`.
2. Направление стажёра берётся из данных сотрудника (`EmployeeProvider` → поле `track`), путь = `common` + `track`.
3. MCP-endpoint `checklist` и API «Моего пути» отдают шаги по `track_id`. Ни одного `if track == "backend"` в коде нет.

**Что делает человек, чтобы добавить, например, трек QA:**
1. Создать `tracks/qa.yaml` по формату (`kind: direction`, `extends: common`, `synthetic: true`, `disclaimer`).
2. Если шаги ссылаются на новые документы или ресурсы — добавить их в сиды базы знаний и в каталог `access` (тоже данные).
3. Указать `track: qa` тестовому сотруднику в сидах.
4. `docker compose restart backend` или «Сбросить демо-данные» → войти учёткой → путь QA на экране.

Минимальный валидный трек (в репозиторий не кладём — QA вне скоупа, это иллюстрация для README):
```yaml
schema_version: 1
id: qa
title: QA (тестовый трек)
kind: direction
extends: common
synthetic: true
disclaimer: "Тестовый трек, не материалы Авито."
source: "Иллюстрация формата"
steps:
  - { id: qa-w1-10, period: week1, order: 10, type: learn, owner: intern,
      title: "Изучи QA-практики команды", help: { kind: track_only } }
```

**Как это доказываем эксперту (без запуска и с запуском):**
| Доказательство | Где | Критерий |
|---|---|---|
| Таблица-тест `TestLoadAllTracks`: обходит `tracks/*.yaml`, каждый файл проходит все 7 правил; отдельный тест на временной папке с `qa.yaml` проверяет, что новый трек появляется в API без изменений кода | Go-тесты, CI | Техническая реализация (15%) |
| Негативные тесты загрузчика: дубль `id`, неизвестный период, ресурс не из каталога, `synthetic` без `disclaimer` → понятная ошибка с именем файла и шага | Go-тесты | Техническая реализация, работоспособность |
| Вход под «стажёром Frontend» → другой путь, плашка «Тестовый трек» | Прототип, шаг README | Внедряемость (30%), безопасность данных (пометка тестового) |
| Раздел README «Добавить трек за 4 шага» + слайд «Направление — это данные» | README, PDF | Внедряемость (30%) |

**Цена и черта отсечения:** контент Frontend-трека готов здесь, поэтому пункт 3 черты отсечения стоит ≈0,5 ч (положить файл, 3 документа базы знаний, 3 ресурса). Загрузчик и его тесты нужны и для Backend, так что отдельной работы под расширяемость нет.
