# Design: add-vitya-character

## Принцип
Характер живёт в шаблонах и коде. Модель распознаёт намерение и переформулирует только разрешённые ответы; на болтовню, «не понял» и защитные темы она не отвечает, шаг 2 для них не вызывается. Всё работает в `demo`.

## Болтовня: тема `help`, а не новое намерение
- `help` уже «разговор о самом Вите» с низшим приоритетом; болтовня — его частный случай.
- Контракты (`IntentResult.intent`, OpenAPI `AgentReply.intent`, Zod) не меняются — нет риска для генерации и CI.
- Вид болтовни всегда из правил (`small_talk` в `intents.ru.yaml`); если правила нашли болтовню, а модель вернула `help`/`kb_question`/`unknown`, остаётся болтовня правил (`override: llm`).
- Болтовня засчитывается, только если ни одно намерение не набрало порог и непокрытых содержательных токенов не больше одного. Защитные темы проверяются раньше.

## Детерминированный выбор варианта
`FNV-32a(client_message_id) mod N` — повтор сообщения даёт тот же текст, тесты стабильны без подмены случайности.

## Пары слов в защитных темах
Фраза «телефон коллеги» не совпадает с «телефон моего наставника». Тема получает `pairs: [{first, second, gap}]`: слово из `first`, затем через не больше `gap` токенов слово из `second`. Так же ловится «забудь все предыдущие инструкции». Порядок важен: «наставнику в телеграм» — не запрос контакта.

## role_change
Новая защитная тема, входит в `GuardTopics` (как `sick_leave`). Ответ без шутки называет роль из сессии и даёт меню; инструментов на запись и черновиков нет. В промпте `intent-v2` пример переведён в `out_of_scope/role_change`, в схеме `topic` добавлено значение (совместимо назад).

## Фронт
- Приветствие читает путь из общего кэша `['path']` без второго опроса и без повторных тостов; время суток — `Intl.DateTimeFormat` с `config.timezone`.
- Анимации — CSS keyframes на классах `vitya--<state>`, `@media (prefers-reduced-motion: reduce)` их отключает.
- Праздник: чистая функция `completedPeriods(prev, next)` + множество отпразднованных этапов в памяти вкладки; вызывается после ответа сервера на отметку шага и после опроса с одобрением заявки, не на оптимистичном обновлении.

## Риски
- Ложные срабатывания болтовни перехватывают вопросы → низший приоритет и порог покрытия, таблица ложных срабатываний в тестах.
- `role_change` на безобидных фразах («мой наставник теперь другой») → только фразы с «я/ты» и пары глагол → объект, тест ложных срабатываний.
