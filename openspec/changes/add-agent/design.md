# Design: add-agent

Полное описание — `docs/09-spec-agent.md` v1.3. Здесь — ключевые решения и ссылки.

## Главный принцип (§0)
Модель предлагает, код решает. LLM только (1) превращает текст в `IntentResult` и (2) переформулирует готовый ответ. Маршрут, права, валидация и запись во внешние сервисы — в Go. Поэтому в `demo` все сценарии проходятся тем же кодом.

## Конвейер (§2)
Предпроверки (дубль `client_message_id`, размер, rate-limit, маскирование ПДн) → контекст (роль, трек, этап, следующий шаг) → распознавание (payload без распознавания; текст — правила всегда, модель опционально) → guard роль × инструмент × объект → MCP-чтение → шаблон ответа → опциональная переформулировка с `ReplyGuard` → события.

## Распознавание (§3, §4, §6)
- Плоская схема `IntentResult`, связи «намерение ↔ параметры» проверяет Go (§3.3).
- Словарь `internal/agent/rules/intents.ru.yaml`: обычные слова, стемминг Snowball при загрузке, отрицание, несколько намерений, алиас ресурса засчитывается только с глаголом доступа.
- Защитные темы (`salary`, `vacation`, `sick_leave`, `personal_data`, `wellbeing`, `evaluation`) побеждают модель.

## Ответы (§7, §9, §10)
- `AgentReply`: `mode`, `intent`, `mascot_state`, `text` с маркерами `[n]`, `sources` с `label`, `actions` (у `copy` — `copy_event`), `pending_action`, `escalation`, `notices`.
- `ReplyGuard`: 7 инвариантов (обязательные значения, маркеры, числа, без URL и HTML, без «регламент Авито», без «создана» до создания). Нарушение → шаблон.
- Переформулировка не вызывается для отказов, ошибок, «не нашёл», уточнений, черновиков и расхождений инструкций.

## Ограничения (§8, §11)
- Заявки — только `POST /api/actions/{id}/confirm`; черновик по модели `docs/10-spec-s3-time-off.md` §8.1 (состояния, `expires_at`, 404/410, повтор → тот же результат).
- Эскалация — редактируемый черновик с «Скопировать»; событие `escalation_copied` идёт через `POST /api/client-events`.
- Права: `actor` только из сессии; guard в оркестраторе и повторно в `mcp-mocks`; закрытые документы отфильтрованы в SQL.
- Веб: текст как текст, санитайзер markdown, cookie `HttpOnly`/`SameSite=Lax`, `Origin` = same-origin по `Host` или `ALLOWED_ORIGINS`.

## Сбои (§13)
Неполная конфигурация LLM и 401/403 → работа как `demo` с плашкой; 3 сбоя подряд → circuit breaker 60 с; флаги `llm_enabled`, `llm_rephrase`; MCP недоступен → `oops` + «Повторить» без дубликатов.

## Риски
- Объём (26 требований, ≈50 тестов): порядок реализации из §15 — основной сценарий не зависит от LLM-части.
- Ложные срабатывания правил: таблицы перефразировок и ложных срабатываний в тестах (§14.3).
